TASK 1 — CTF-001A
Prevent Superseded Resources from Entering Current AI Context
Priority: P0 — Critical
Current status: Almost complete

Problem
The Context Compiler correctly limits AI access using operation-specific Context Policies.

However, a superseded resource may still enter the current AI context if:

the old resource ID is still referenced from Creation Memory;

both old and replacement versions exist;

_select_records() does not explicitly exclude superseded records.

Example:

REALITY v1 — superseded
REALITY v2 — current
Both must not appear in normal operational AI context.

Required behavior
By default:

Historical / superseded resource
→ remains in Creation Genealogy
→ remains available for audit/history
→ must NOT enter current operational AI context
Only an operation explicitly requiring historical comparison may request superseded versions.

Required implementation
Add to Context Policy:

include_superseded_history: false
Default:

false
Update resource selection logic so records with:

record.superseded_by is not None
are excluded unless:

include_superseded_history: true
Creation Memory references must also be normalized before compilation.

If the memory root references an old version and a newer active version exists:

old ref → resolve → current active resource
where appropriate.

Files/modules to review
packages/ctf_domain/context_compiler.py
packages/ctf_domain/context_policy.py
prompts/context-policies.yaml
packages/ctf_domain/repository.py
packages/ctf_domain/service.py
Required tests

test_superseded_resource_remains_in_genealogy
test_history_policy_can_explicitly_include_superseded_resource
test_creation_memory_stale_ref_resolves_to_current_resource
Acceptance Criteria
Normal AI operations receive only current resource versions.

Historical data remains intact.

No Creation Genealogy record is deleted.

No silent overwrite occurs.

Explicit historical-analysis policies may include old versions.

document_jobs

attachment_id
status
attempt

available_at

SELECT ...
FROM document_jobs
WHERE status IN ('QUEUED', 'RETRY_WAIT')
  AND available_at <= now()
ORDER BY created_at
FOR UPDATE SKIP LOCKED
LIMIT 1;
Then update the selected row to:

CLAIMED
inside the same transaction.

class PostgresDocumentJobQueue(DocumentJobQueue):
